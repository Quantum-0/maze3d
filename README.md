# 3D Low-Poly Maze — лабиринт с Twitch-интеграцией

Процедурная 3D-игра-лабиринт в low-poly стилистике на **Three.js** (Vanilla JS + Vite, без внешних 3D-моделей — вся геометрия генерируется кодом). Игра задумана под стримы: в планах — интеграция с чатом Twitch, где зрители смогут спавнить монстров, ловушки и лечилки герою.

**Демо:** https://quantum-0.github.io/maze3d/

---

## Возможности

- **Процедурная генерация**: идеальный лабиринт (Recursive Backtracker) + пробивание 15–20% внутренних стен для создания циклов; старт и финиш разводятся на максимальную дистанцию двойным BFS.
- **4 биома**: Зима (озеро, горы, ели, фонари), Лес (густой периметр, поляны с кострами, парковые дорожки и скамейки, лианы), Техно (эстетика дата-центра: серверные стойки, хладагентные трубы с бегущим светом), Подземелье (факелы, сталагмиты, капающая вода, свет не проходит сквозь стены).
- **Два режима**: визуализатор (свободная облётная камера, минимапа, смена тем) и игра (рыцарь с мечом и фонарём, таймер, HP, победа на алтаре).
- **Ловушки**: струи огня/кислоты/плазмы/пара из стен, напольные шипы (авто и по приближению), обвалы с растущей тенью, ложные стены (наклоняются и падают на игрока), прорубаемые препятствия (снеговики/кусты/доски/провода, 3 HP).
- **Враги**: 3 паттерна ИИ (патруль+погоня по BFS, засада, сквозь стены), дальний и ближний бой, процедурные модели по темам, смерти с падением и осколками.
- **Управление**: клавиатура + мышь + полный геймпад (движение, бег, прыжок, атака, камера, навигация по меню).
- **Пространственный звук**: громкость по дистанции, стерео-панорама (до 75/25), все эффекты синтезируются WebAudio.
- **Визуал**: flat shading, PCFSoft-тени, туман, UnrealBloom, процедурные фасетные нормал-мапы, системы частиц (огонь, дым, светлячки, снег).

## Запуск и сборка

Требуется Node.js 20+.

```bash
npm install        # зависимости
npm run dev        # dev-сервер на http://localhost:5173
npm run build      # production-сборка в dist/
npm run preview    # локальный просмотр собранного
```

Сборка под GitHub Pages использует переменную `BASE_URL` (см. workflow): vite берёт из неё `base`, локальная разработка идёт от корня.

### Деплой

`.github/workflows/deploy.yml` на каждый push в `main`/`master` собирает проект (`BASE_URL=/maze3d/`) и публикует через `actions/deploy-pages`. В настройках репозитория: Settings → Pages → Source = **GitHub Actions**.

## Управление

| Действие | Клавиатура/мышь | Геймпад |
|---|---|---|
| Движение | WASD / стрелки | левый стик / крестовина |
| Бег | Shift | RT |
| Прыжок | Space | B |
| Атака | ЛКМ | A |
| Камера | зажатая ПКМ + мышь | правый стик |
| Меню / пауза | Esc | Menu |

В визуализаторе: ЛКМ — облёт, колесо — зум, ПКМ — панорама.

## Архитектура

```text
/src
  /core        Engine.js — рендерер, камера, bloom-композер, цикл; utils.js — сид-RNG и пр.
  /maze        Maze.js — генератор (backtracker + циклы + BFS); colliders.js — AABB стен
  /world       ThemeManager.js — смена тем; themeHelpers.js — GeoBatch (слияние геометрии),
               фасетные нормал-мапы, порталы; themes/ — 4 биома
  /entities    Player.js — рыцарь, физика, анимации; Enemy.js — враги и EnemyManager
  /traps       TrapManager.js, trapTypes.js (струи/шипы/обвалы/стены/препятствия),
               Debris.js (обломки), Sfx.js (синтез звука), Smoke.js (дым)
  /ui          HUD.js — меню, панель, минимапа, HP, оверлеи, геймпад-навигация
  main.js      Точка входа: режимы, ввод, камера, победа/смерть
```

Ключевые решения:

- **GeoBatch** — вся статика биома клонируется с матрицами и сливается в один меш на материал (`mergeGeometries`): сотни объектов = единицы draw call'ов.
- **Фасетные нормал-мапы** — триангуляция с джиттером, каждому треугольнику своя наклонная нормаль из периодического волнового поля (соседние фасеты коррелированы, тайлы бесшовные); даёт «объём» стенам без текстур-картинок.
- **ИИ** — зрение трассировкой по сетке стен (не видят сквозь углы), погоня по общему BFS-полю дистанций до игрока (пересчёт 2 раза/сек на всех врагов сразу).
- **Sfx** — все звуки (щелчки, шипение, удары, треск, лазер) генерируются осцилляторами/шумом WebAudio с цепочкой gain → StereoPanner → gain по дистанции.

## Этапы разработки

### Этап 1 — модель лабиринта
Recursive Backtracker по сетке N×M, удаление 15–20% внутренних стен (циклы для маневрирования), двойной BFS для максимально удалённых старта/финиша, путь решения для декора. Автотесты на 4 размерах: проходимость всех клеток, корректность пути, целостность периметра.

### Этап 2 — процедурный мир и 4 биома
ThemeManager + фабрики декора из примитивов (конусы/икосаэдры/смещённые боксы). Итерации по вашим отзывам:
- Зима: ёлки со снежными воротниками, замёрзшее озеро с трещинами, кольцо гор и холмов за периметром, снегопад, фонари вдоль маршрута.
- Лес: деревья только у стен (проходы свободны), фон — равномерное заполнение периметра лесом с плотностью/размером, растущими к горизонту, поляны с кострами, дорожки из камней, скамейки к стенам, арки-лианы строго в коридорах, редкая трава, грибы.
- Техно: переведена с неона на эстетику дата-центра — серверные панели с LED, трубы с хладагентом по бокам стен, верхние люминесцентные лампы в случайных точках, спокойный ambient.
- Подземелье: фасетный каменный пол, россыпи камней, сталагмиты у стен, факелы с дымом, капли с «потолка» с лужами; глобальный свет выключен, стены перекрывают свет.

### Этап 3 — игрок
Процедурный рыцарь (меч в правой руке, фонарь в левой, прожектор с тенями в подземелье), движение относительно камеры с инерцией, коллизии круг-vs-AABB со скольжением, следящая камера с орбитой (ПКМ/стик) и клампом по вертикали, прыжок/бег/атака, победа на алтаре с таймером, стартовый экран с выбором режима (визуализатор/игра) и настройкой локации.

### Этап 4 — ловушки
TrapManager (зоны старта/финиша исключаются), 5 типов ловушек с неявными маркерами, HP с баром, урон (вспышка/виньетка/отбрасывание/неуязвимость), смерть и респаун, обломки с физикой, синтезированный звук. Позднее — пространственное аудио.

### Этап 5 — враги
Процедурные модели (голем, гоблин/тролль, дрон, паук/плевун, призрак, огонёк), паттерны: патруль→погоня, засада, фазовый (сквозь стены). 45% ходоков — дальнобойные (навесные снаряды с баллистикой / лазер с прицельным лучом). Смерть — падение с последующим рассыпанием, коллизии игрок↔враг↔враг↔стены, грейс-период на старте.

### Этап 6 — Twitch GameAPI (в планах)
`window.GameAPI` для спавна монстров/ловушек/лечилок зрителями через tmi.js/EventSub и глобальные события (погасить свет, инвертировать управление и т.п.).

## Баги и их решения

Накопленная за разработку «зоология» — полезна для понимания кодовой базы:

1. **Горы накрывали лабиринт, озеро пропадало (зима).** Причина: радиальное размещение у квадратного лабиринта — углы дальше от центра (ext/2·√2), а основания гор были шире дистанции. Решение: размещение по периметру (4 стороны) + жёсткий кап радиуса основания через чебышевскую дистанцию; озеро — строго за одной из сторон.

2. **Деревья/скамейки в лесу перегораживали проходы.** Декор стоял у центров клеток. Решение: угловое размещение (spreadMin 1.2–1.45 от центра, у самых стен), уменьшение масштаба; скамейки — только у реальных стен (проверка `cell.walls`), вплотную и лицом к дорожке.

3. **Фоновый лес — literal круги.** Концентрические кольца давали видимую окружность и наезды на углы. Решение: равномерный square-сэмплинг с чебышевской защитой + плотность и размер, растущие с дистанцией — горизонт закрыт без «колец».

4. **Снег на ёлках/горах выглядел «насаженным конусом».** Шапка висела над вершиной. Решение: снежные воротники на каждом ярусе с совмещёнными апексами; у гор — конус, конгруэнтный склону (радиус по пропорции высоты, +12% нахлёста, вершина перекрывает деформированный пик).

5. **Арки-лианы стояли в тупиках и углах, «дуга» поперёк прохода.** Решение: строгое условие коридора (стены с двух боков, проходы с двух торцов) и разворот на 90° — теперь арка перекидывается через коридор.

6. **Факел наклонялся «от стены» (палка "/").** Знак поворота: rotation.z = +0.55 задирал основание. Решение: -0.55, основание в кронштейне, огонь на верхушке, наклонённой в коридор.

7. **Техно — пересвет неоном.** Решение: ребаланс в дата-центр (см. этап 2), bloom понижен, лампы подняты и randomized, ведущая полоса пути убрана (путь игрок ищет сам).

8. **Фасетные нормал-мапы — «шахматная доска».** Первая версия давала нейтральные нормали внутри треугольников и резкие рёбра; вторая — слишком крутые фасеты (~45°). Решение: наклон по центроиде из волнового поля, масштаб 0.15 и жёсткий потолок 0.28 → характерные 4–15°.

9. **Меч оказался «в левой руке».** У модели, смотрящей на +Z, правая сторона — локальный -X. Решение: swap рук + фонарь на левой руке, свет висит на фонаре.

10. **Ложная стена падала «вбок» (вертикальные сегменты, всех тем).** Наклон вешался на объект с уже установленным rotation.y = π/2 — порядок Эйлера XYZ складывался в наклон вдоль стены. Решение: pivot-группа для падения, mesh с yaw внутри.

11. **Шипы — слишком явная плита.** Решение: миниатюрные цилиндры (r=0.16, h=0.07) цвета пола в местах шипов, подсветка только в фазе предупреждения.

12. **Струя — «кружочки».** Решение: шейдерные частицы — мягкие пятна exp-профиля с градиентом ядро→середина→кромка по теме, ускорение и турбулентность вдоль струи, аддитивный блендинг + bloom.

13. **Смерть врага не читалась.** Решение: анимация — падение вокруг ступней (летающие падают и сжимаются), затем всплеск осколков.

14. **Призраки избивали на старте.** Серия фиксов: спавн фазовых ≥8 клеток, задержка пробуждения, погоня только при LOS (или вплотную <4.5), и финально — грейс-флаг: враги не агрятся и не атакуют, пока игрок не сошёл со стартовой клетки (гасится и уже начатая погоня при паузе).

15. **Дальнобойных можно было продавить сквозь стену.** Отталкивание игроком не проверяло стены. Решение: resolveWalls — тот же circle-vs-AABB выталкиватель по стенам и блокирующим ловушкам (фазовые — исключение, они сквозные по дизайну).

16. **Лапы паука торчали вверх.** Тот же класс бага, что у факела: зеркальный знак rotation.z. Решение: -side*0.68, длина 0.72, центр опущен — лапы идут от корпуса к земле.

17. **Огонёк воспринимался как фонарь.** Решение: в режиме погони — ярко-красный мигающий (эмиссия+свет пульсируют ~2.5 Гц), в покое — тёплый янтарный.

18. **Игрока разворачивало от отбрасывания.** Facing следовал вектору скорости, куда вписывался knockback. Решение: поворот только по направлению ввода — толчки и скольжение вдоль стен больше не вращают персонажа (бонус: нет «косит вбок» при скольжении).

19. **Дым «светился» (дважды).** Сначала серый alpha-дым на тёмном фоне выглядел светящимся; multiply-режим не помог (сквозь тонкий дым просвечивал HDR-огонь ниже порога... и в итоге всё равно белый). Пуленепробиваемое решение: обычный альфа-блендинг с жёстко зажатым тёмным цветом частицы (≈0.07–0.09 серого, без белого RGB текстуры) — физически не может быть ярким.

20. **Мелочи инфраструктуры**: git «dubious ownership» (safe.directory), случайный коммит личных папок (amend + .gitignore), цилиндры-трубки не ложатся поворотом вокруг Y (пре-поворот геометрии rotateZ(π/2)).
